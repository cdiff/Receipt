# Lean Engineering Standards (rules/lean-engineering.md)

우리 팀의 코드 품질, 복잡도 억제 및 검증 표준입니다.

---

## 1. 실용적 TDD (Pragmatic TDD) 원칙
- **선-테스트 (Strict TDD)**:
  - 계산 로직, 상태 머신 전이, 보안/권한 검증, 재현된 버그 패치
  - 반드시 실패하는 테스트 작성 ➔ 최소한의 구현 ➔ 테스트 통과 확인
- **후-검증 (Post-Verification)**:
  - 단순 UI 컴포넌트, 정적 레이아웃/스타일링, 보일러플레이트 코드
  - 구현 후 렌더링/빌드 검증

---

## 2. Karpathy 복잡도 억제 원칙 (Simplicity First)
- **외과수술적 변경 (Surgical Edits)**: 요청받은 기능과 무관한 주변 코드를 임의로 리팩토링하거나 건드리지 않는다.
- **오버엔지니어링 금지**: 미래에 필요할지도 모른다는 이유로 쓰이지 않는 추상화 계층이나 복잡한 제네릭 구조를 도입하지 않는다.
- **기존 패턴 존중**: 프로젝트 내 이미 사용 중인 네이밍, 아키텍처(MVI/MVVM), 디펜던시 패턴을 최우선으로 따른다.

---

## 3. 검증 표준 (Evidence Before Assertion)
- "정상 작동할 것입니다", "수정이 완료되었습니다"라는 주장은 반드시 실행된 터미널 로그, 테스트 결과, 빌드 성공 증거를 확인한 후에만 진술한다.
